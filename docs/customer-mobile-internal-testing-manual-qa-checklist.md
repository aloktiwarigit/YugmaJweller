# Customer Mobile Internal Testing Manual QA Checklist

Scope: customer app functionality visible in `apps/customer-mobile`, tested on a Moto G Android device. Use a clean install when validating auth/bootstrap, then an authenticated test customer with seeded catalog, wishlist, bookings, loyalty, and timeline data where available.

Status legend: `Not Run`, `Pass`, `Fail`, `Blocked`, `N/A`.

| Functionality | How to test on Moto G | Expected result | Status |
| --- | --- | --- | --- |
| App cold start and tenant bootstrap | Install/open the app from a stopped state on mobile data and Wi-Fi. Repeat once with the API/tenant unavailable if possible. | Splash clears, tenant brand header appears, valid sessions route to Home, unauthenticated users route to Welcome, tenant failure shows retry UI. | Not Run |
| Welcome phone auth | From a signed-out state, enter invalid phone values, then a valid 10-digit number, request OTP, enter invalid and valid OTP values. | Invalid input shows inline errors; valid phone advances to OTP; valid OTP signs in and lands on the tabbed app. | Not Run |
| Dev auth shortcut | In a dev build with `devAuth` enabled, tap the dev continue action. | A mock customer session is created and the app routes to Home without OTP. | Not Run |
| Bottom tab navigation | Tap Home, Browse, Wishlist, and Profile tabs repeatedly. Rotate no more than the device default portrait flow unless required by build. | Correct tab content loads, active tab styling changes, no blank screens, no unexpected sign-out. | Not Run |
| Home storefront header and category rail | On Home, inspect brand header, horizontal category chips, and open the browse drawer from the rail. | Header uses tenant branding; chips are tappable; drawer opens and closes cleanly. | Not Run |
| Home storefront sections | Scroll Home top to bottom, including hero, rates, category tiles, new arrivals, gift chips, top sellers, everyday links, premium links, promise pillars, and footer accordions. | Sections render without overlap; product rows scroll horizontally; links navigate to filtered Browse or support pages; footer accordions expand/collapse. | Not Run |
| Storefront drawer | Open the drawer, expand each top-level browse group, scroll chip shelves, tap representative links, and close via scrim and close button. | Drawer animates in/out, expanded groups show links, tapped links navigate to Browse with relevant filters/search. | Not Run |
| Browse search | On Browse, type a SKU/category/metal term, wait for debounce, clear the field, and test a no-result term. | Result count and grid update; no-result state is readable; clearing search restores broader results. | Not Run |
| Browse filters | Open Filter, test metal, purity, price, style, occasion, and in-stock sections; apply filters; remove chips; clear all. | Sheet opens from bottom; selections persist until applied; active chips appear; removing/clearing resets results and count. | Not Run |
| Browse sorting and pagination | Open Sort, select each sort option at least once, then use next/previous pagination when available. | Sort modal closes after selection; grid refreshes; pagination buttons move between result pages without losing active filters. | Not Run |
| Browse product cards | Open available and unavailable products from Browse. Verify image/fallback image, SKU, HUID badge, price/contact text, and unavailable state. | Product cards are tappable; unavailable products still open details; image and price states are clear. | Not Run |
| Product detail base content | From Browse/Home, open a product detail page and scroll through gallery, title, SKU, category, trust strip, weights, and price breakdown. | PDP loads without clipping; fallback/error state appears for invalid product; back returns to previous screen. | Not Run |
| Product gallery and recommendations | On PDP, swipe product images and tap a recommended product if recommendations are present. | Gallery swipes smoothly; recommendation opens the selected PDP. | Not Run |
| PDP wishlist actions | On PDP, tap wishlist in the action row and sticky bottom bar; verify Wishlist tab after add/remove. | Heart selected state updates optimistically; Wishlist tab reflects added/removed item after refresh. | Not Run |
| PDP share action | Tap Share from PDP and dismiss or complete the Android share sheet. | Native share sheet opens with product title/SKU/price when available; dismissing does not crash. | Not Run |
| PDP HUID verification | For a HUID product, tap HUID QR scan, deny and allow camera permission if possible, enter short/invalid and valid manual HUID values. | Modal handles camera/manual modes; invalid HUID warns; valid submission shows verified or mismatch result and closes modal. | Not Run |
| PDP reviews | On a product with reviews, expand beyond the first six if available, then submit a review as an authenticated user. | Reviews show rating/date/customer text; expand reveals more; review form validates and submits or shows clear error. | Not Run |
| Try-at-home gated state | While signed out, deep link or navigate to Try at Home. | Screen asks the user to log in and does not show booking controls. | Not Run |
| Try-at-home booking | Signed in, open Try at Home, select and deselect products up to the max, attempt over max, submit booking. | Submit is disabled with zero selection; over-limit products disable; successful booking shows confirmation with dispatch/return dates when present. | Not Run |
| Rate-lock gated state | While signed out, deep link or navigate to Rate Lock. | Screen asks the user to log in and does not show booking controls. | Not Run |
| Rate-lock booking and payment | Signed in, open Rate Lock, verify current rate, submit empty/invalid deposit, submit valid deposit, tap Razorpay payment. | Invalid deposit shows error; valid booking shows locked rate and expiry; payment opens the signed payment URL or shows a clear error. | Not Run |
| Wishlist screen | With empty, populated, and network-error states if possible, open Wishlist and remove an item. | Empty/error copy is readable; retry appears on load error; removal shows spinner and updates the list or error message. | Not Run |
| Profile summary and timeline tabs | Open Profile, verify name/phone, loyalty points card, and each timeline tab: purchases, custom orders, rate locks, try-at-home, reviews. | Profile data renders; tabs switch without remount flicker; empty/loading/error states are understandable. | Not Run |
| Loyalty page | Navigate to Loyalty if exposed/deep linked, test loading, populated, empty transactions, and retry after error. | Points, tier badge, progress, transactions, empty state, and retry are readable and consistent. | Not Run |
| Support page | Navigate from Home footer or deep link to Support, use Back, and open return policy from the primary action. | Support page lists order/rate-lock/try-at-home/policy guidance; Back works; policy link opens Policy. | Not Run |
| Return policy page | Open Policy, test loading, configured policy, and no-policy fallback if possible. | Policy text displays in a readable card; fallback explains policy is unavailable; Back works. | Not Run |
| Size guide page | Open Size Guide, switch between rings, bangles, and chains tabs, then scroll tables. | Selected tab styling changes; each table displays expected size rows without horizontal clipping. | Not Run |
| Account sign-out | From Profile, tap Sign out. Reopen app from stopped state. | Session is cleared; user lands on Welcome and protected tabs redirect to auth. | Not Run |
| Delete account validation | From Profile, open Delete Account, test Back, choose each reason, choose Other and type text, enter wrong confirmation phrase. | Submit remains disabled until a reason and exact confirmation phrase are provided; Other text field appears only for Other. | Not Run |
| Delete account submission | With a disposable test customer, submit deletion and also test blocked API states if seeded: open invoices, already requested, in-flight try-at-home. | Success signs out and shows done screen; blocked states show specific error copy without clearing the session. | Not Run |
| Mobile usability pass | On Moto G, scan all screens for touch targets, keyboard overlap, bottom safe area, loading spinners, Hindi text rendering, and scroll boundaries. | Controls are tappable, text is legible, keyboard does not hide active inputs, sticky bars do not cover content, no visual overlap. | Not Run |
| Offline/poor network pass | Toggle airplane mode or use poor network while loading Home, Browse, PDP, Wishlist, Profile, Rate Lock, and Try at Home. | Screens show loading/error/empty states without crashing; retry actions work when network returns where provided. | Not Run |
| Analytics smoke check | During a test run, navigate routes and trigger wishlist add/remove plus booking creation when possible; inspect PostHog/Sentry dev logs or dashboard. | `page_view`, wishlist, and booking events are emitted with expected identifiers; no unexpected Sentry errors. | Not Run |
